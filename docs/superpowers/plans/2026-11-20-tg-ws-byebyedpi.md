# TG-WS Proxy by derigava_ — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Один APK сохраняет существующий TG-WS и заменяет ByeByeDPI на поддерживаемых устройствах, включая инструменты оригинала в интерфейсе TG-WS.

**Architecture:** Три независимые границы: неизменяемый снимок upstream, Android-адаптер двух режимов, собственный Compose-интерфейс. Состояние движков принадлежит сервисам; UI посылает команды и подписывается на состояния. CI меняет снимок через проверяемый PR, а не в момент сборки подписанного APK.

**Tech Stack:** Kotlin, Compose, Android foreground service и VpnService, NDK/JNI, Gradle, существующее Python-ядро TG через Chaquopy, GitHub Actions на Linux.

**Spec:** [Согласованный дизайн](../specs/2026-11-20-tg-ws-byebyedpi-design.md).

## Global Constraints

- Android 7.0+ (API 24), ARM64; сохранить x86_64 для эмулятора. ARM64 Android TV/BOX: управление без тача.
- `io.github.derigava.tgwsproxy`, действующая подпись, растущий versionCode, существующие ключи настроек и команды TG остаются совместимыми.
- `TG-WS Proxy` — название, `by derigava_` — подпись. Исходный `CursorSwitch` — эталон обеих кнопок. Не переносить оформление браузерного макета.
- Без root, второго APK, загрузки исполняемого модуля на телефон или молчаливого захвата VPN. SOCKS5 не выдавать за охват всего устройства. Не менять политику обновления Flowseal.

## Review Focus

1. Сторонний VPN появился между проверкой и стартом, отказ или lockdown: не завладеть слотом без согласия (§3).
2. Совпадение портов и повторная команда stop: работающий соседний сервис остаётся доступен (§2–3).
3. Апгрейд со старой версии или смерть процесса не меняют секрет и не запускают VPN (§3, §7).
4. Смена ABI/сабмодуля или upstream-тег с тем же именем, но другим SHA: CI останавливает обновление (§1, §6).
5. Повреждённый импорт и управление пультом/крупным шрифтом не лишают пользователя доступа к настройкам (§4–5).

## Карта работ

`K` ниже означает `app/src/main/java/com/amurcanov/tgwsproxy/`. Существующие файлы: `K/ProxyService.kt` (TG), `K/SettingsStore.kt`, `K/BootReceiver.kt`, `K/MainActivity.kt`, `K/ui/{ConnectionTab,SettingsTab,LogsTab,InfoTab}.kt`, `app/src/main/AndroidManifest.xml`. Новые файлы перечислены по этапам. Не переносить TG в новый runtime ради симметрии.

Порядок: **1 → 2 → 3 → 7**; **4** (UI с тестовым контроллером) после фиксации контракта 2, **5** после инвентаризации 1 и навигации 4; **6** после 1 параллельно мобильной разработке. Этап 7 собирает всё. Каждый этап сдаётся отдельным коммитом/PR; недоделанные экраны не попадают в публичный релиз. Для тестовых этапов: сначала выполнить указанную проверку до изменения и увидеть ожидаемый отказ, затем повторить после изменения; красный тест по иной причине не считать доказательством.

### 2. Собрать движок и доказать работу SOCKS5 без VPN

- [ ] Добавить тест контракта `DpiControllerTest`: привязка занятого порта → `Failed`, не `Running`; два stop подряд → `Off`; экземпляр TG остаётся доступен. Предлагаемый контракт в `K/dpi/DpiController.kt`: `DpiMode { VPN, SOCKS5 }`, `DpiState` с Off/Starting/Running(mode)/Stopping/Failed(reason), `state: StateFlow<DpiState>`, `start(config: DpiConfig)` и `stop()`. Успешный старт подтверждает готовый движок, а не факт отправки Intent.
- [ ] Подключить `:dpi-runtime` в `settings.gradle.kts`, нативную сборку в `dpi-runtime/build.gradle.kts`, адаптер JNI и локальный foreground-сервис. Использовать исходники из этапа 1. Приватные команды, раздельные notification ID и namespace настроек. Собирать обе ABI в Linux/WSL; не добавлять скачивание библиотек при запуске.
- [ ] Проверка: `./gradlew :app:testEmulatorDebugUnitTest :app:assembleArm64Debug :app:assembleEmulatorDebug`; на эмуляторе пройти SOCKS5-handshake и получить ответ тестового HTTP-сервера; системный VPN не запрошен. При занятом порте TG продолжает отвечать. Коммит `feat: run pinned ByeByeDPI in local proxy mode`.

### 3. Системный VPN и жизненный цикл двух модулей

- [ ] В `K/dpi/VpnStartPolicy.kt` выделить чистое решение `decide(request: VpnStartRequest): VpnStartDecision`. Проверить таблицу: off + собственное разрешение → запуск; активный/неизвестный сторонний VPN → выбор SOCKS5 / замена с явным согласием / отмена; отказ, потеря согласия или lockdown → нет несанкционированного запуска. Состояние перепроверять перед стартом. При невозможности надёжно определить владельца показывать предупреждение консервативно.
- [ ] Объявить защищённый `VpnService` в manifest; связать TUN с движком и исключить исходящие соединения обоих движков из собственного туннеля. Реализовать all-apps по умолчанию и списки приложений. Развести команды, уведомления и восстановление. В `K/BootReceiver.kt` учитывать сохранённый opt-in на каждый модуль: обновление само его не создаёт. Внешние команды ByeByeDPI требуют видимого подтверждения; существующие TG-ярлыки/плитка не меняют адресата.
- [ ] Проверка на устройстве: TG отдельно, VPN отдельно, оба одновременно; остановить сначала левый, затем повторить с правым первым. Подтвердить маршруты контрольным запросом и TG-подключением, а не только цветом кнопки. Повторить для стороннего VPN, SOCKS5, отказа, отзыва, смены сети и перезапуска процесса. Сверить уведомления и состояния после повторного открытия. Коммит `feat: isolate VPN routing and service lifecycles`.

### 6. Обновление вслед за upstream

- [ ] Создать `.github/workflows/byebyedpi-update.yml` с суточным cron и ручным запуском. Тесты решения по фиктивным релизам: тот же тег/SHA → ничего; prerelease → пропуск; новый stable → один PR; повторный запуск → без дубликата; перемещённый тег → ошибка. Тесты не создают реальных PR.
- [ ] Права записи только job подготовки PR; зависимости Actions закреплены SHA. Не выполнять скачанный upstream-код с пишущим токеном; не передавать ключи подписи. PR содержит lock, diff исходников/лицензий и изменения списка возможностей. Обеспечить запуск проверок даже если PR создан `GITHUB_TOKEN` (явный запуск доверенного проверочного workflow либо токен GitHub App с минимальными правами). Не полагаться только на событие `pull_request`, которое токен бота может не породить.
- [ ] В `.github/workflows/android-release.yml` дополнить `prepare/verify` офлайн-проверкой снимка и тестами/ABI. Другие условия Flowseal и подписания не ослаблять. В тестовой ветке доказать «изменился upstream → открыт один PR → проверки запущены → без ревью нет публикации»; прогнать откат на прошлый lock с новым versionCode. Коммит `ci: propose verified ByeByeDPI updates`.
