Эталон для сравнения — официальный релиз **ByeByeDPI v.1.8.2**
(`romanvht/ByeByeDPI`), тег `v.1.8.2`, Git-коммит
`96a3c1ff555043d915af814aa4f0e9a572c89aba`.

- Оригинальный `applicationId`: `io.github.romanvht.byedpi`, `versionCode 1820`,
  `versionName "1.8.2"`, `minSdk 21`, `targetSdk 34`, `compileSdk 36`.
- ABI оригинала: `armeabi-v7a`, `arm64-v8a`, `x86`, `x86_64`.
- Лицензия оригинала: **GPL-3.0-only** (файл `LICENSE`, SHA-256
  `3972dc9744f6499f0f9b2dbf76696f2ae7ad8af9b23dde66d6af86c9dfb36986`).
- Рекурсивные зависимости (git-сабмодули, закреплены в `upstream/byebyedpi.lock.json`,
  источники вендорены байт-в-байт по путям вложенных gitlink'ов, лицензии каждого уровня — в lock):
  - `app/src/main/cpp/byedpi` → `https://github.com/hufrea/byedpi.git` @
    `ba532298de7b28cfe854aea83d061369d13ca290` (MIT);
  - `app/src/main/jni/hev-socks5-tunnel` → `https://github.com/heiher/hev-socks5-tunnel.git` @
    `4d6c334dbfb68a79d1970c2744e62d09f71df12f` (MIT; внутри — `third-part/wintun/LICENSE.txt`,

    - `src/core` → `https://github.com/heiher/hev-socks5-core` @
      `4be2e621813ba0315cfacd995bf501bde91d6996` (MIT);
    - `third-part/hev-task-system` → `https://github.com/heiher/hev-task-system` @

`upstream/byebyedpi/`; контрольные суммы — в `upstream/byebyedpi.lock.json`.

## Как читать таблицы

| Колонка | Значение |
|---|---|
| **ID** | Стабильный идентификатор действия/настройки эталона. |
| **Вход** | Что делает пользователь или внешний вызывающий. |
| **Результат оригинала** | Наблюдаемое поведение ByeByeDPI v.1.8.2 для этого входа. |
| **Экран TG-WS** | Где в TG-WS планируется эквивалент (по решениям дизайн-спеки). `—` = отдельного элемента нет (поглощено другим элементом). |
| **Проверка** | `AT` — автоматический тест, `РП` — воспроизводимая ручная проверка на устройстве. |

> **Статус наблюдения.** Процедуры в колонке «Проверка» описывают, *что* проверить;
> фактического наблюдения на устройстве ещё не выполнялось (этап задачи 1 — снять
> эталон до переноса). Все пункты, требующие устройства, считаются **pending**
> до прохождения соответствующей проверки в задаче интеграции. Здесь ничего не
> помечено как «пройдено» заранее.

## Сознательные отличия TG-WS от эталона

Эти отличия закладываются намеренно и не являются пробелами паритета.

| ID | Отличие | Обоснование |
|---|---|---|
| D-01 | Собственный `applicationId` `io.github.derigava.tgwsproxy` (у оригинала `io.github.romanvht.byedpi`) | Требование спеки: сохранить подпись и package ID TG-WS. Автоматизации, адресующие package ID оригинала, не поддерживаются и не обещаются. |
| D-02 | Все экраны ByeByeDPI воссоздаются на Compose в стиле TG-WS | Решение пользователя: единый интерфейс; переиспользование сервисов/движков через адаптер, без перекрашивания готовых экранов. |
| D-03 | Подтверждение внешних команд | Внешние приложения не получают безусловного права менять стратегию или включать сервис; подтверждение как у существующих действий TG. |
| D-04 | Брендинг «TG-WS Proxy, by derigava_» и иконка-кандидат `11-route-e` | Название/подпись продукта; авторство обоих upstream сохраняется. |
| D-05 | Логи разделяются по источнику (TG / ByeByeDPI) | Требование спеки: общие доступы/обновления в одном месте, но логи по источнику. |

## Неустранённые расхождения и pending

- **Наблюдение на устройстве не выполнялось** (этап задачи 1). Все `РП`-пункты матрицы
  требуют фактического прогона на поддерживаемом устройстве в задаче интеграции;
  до этого они числятся **pending**, ни один не помечен как пройденный.
- **Нативная сборка hev-socks5-tunnel** не собирается на Windows (README); в TG-WS
  сборка планируется через WSL/CI на Linux. Пока CI-задача не создана — pending.
- **Чтение приватных данных чужого APK и поддержка package ID оригинала в сторонних
  автоматизациях** не обещаются (см. D-01).
- Оригинал использует XML/View + Material; визуальное совпадение не является целью —
  целью является эквивалент поведения (см. D-02).
