# Автоматическая съёмка скриншотов

`capture.py` поднимает уже установленное (или только что собранное) приложение в
эмуляторе, проходит его экраны и складывает готовый комплект изображений для
README: `raw/`, `extras/`, `manifest.json`, `capture-report.md` и контактный лист.

Скриншоты настоящие. Скрипт не правит ни код, ни ответы сети, ни состояние
сервисов: «ПОДКЛЮЧЕНО» снимается только тогда, когда прокси и VPN действительно
поднялись. Если экран получить не удалось, шаг помечается в отчёте, а съёмка
продолжается со следующим.

## Что нужно

| Компонент | Требование |
|---|---|
| Android SDK | platform-tools (`adb`), emulator, build-tools |
| Системный образ | x86_64, API 35: `system-images;android-35;google_apis_ps16k;x86_64` |
| AVD | 1080×2400, density 420, 4 ГБ RAM (см. ниже) |
| JDK | 17+ для сборки APK |
| Python | 3.10+; `pillow` — только для контактного листа |
| Сборка | `./gradlew :app:assembleEmulatorDebug` (flavour `emulator`, ABI x86_64) |

Релизные APK проекта собираются под ARM64 и в x86_64-эмулятор не ставятся —
для съёмки используется debug-сборка flavour `emulator`. Производственная
конфигурация при этом не меняется.

### AVD

Если в системе есть `avdmanager`:

```bash
sdkmanager "system-images;android-35;google_apis_ps16k;x86_64"
avdmanager create avd -n ByeBye_Shots -k "system-images;android-35;google_apis_ps16k;x86_64" -d pixel_7
```

Затем в `~/.android/avd/ByeBye_Shots.avd/config.ini` выставить:

```ini
hw.lcd.width = 1080
hw.lcd.height = 2400
hw.lcd.density = 420
hw.ramSize = 4096
hw.cpu.ncore = 4
hw.gpu.mode = swiftshader_indirect
```

Без `avdmanager` достаточно создать каталог `ByeBye_Shots.avd` с таким
`config.ini` (плюс `ByeBye_Shots.ini` с `path=` и `target=android-35`) — эмулятор
сам создаст разделы при первом запуске с `-wipe-data`.

## Запуск

```bash
# 1. Собрать APK для эмулятора
./gradlew :app:assembleEmulatorDebug

# 2. Снять комплект (эмулятор уже запущен)
python docs/assets/screenshots/automation/capture.py \
    --apk app/build/outputs/apk/emulator/debug/app-emulator-debug.apk

# 3. Или поднять AVD и снять всё одной командой
python docs/assets/screenshots/automation/capture.py \
    --apk app/build/outputs/apk/emulator/debug/app-emulator-debug.apk \
    --avd ByeBye_Shots
```

Полезные ключи: `--serial emulator-5556`, `--out <каталог>`, `--keep-data`
(не очищать данные приложения), `--skip-strategy-test` (не гонять автоподбор
стратегий, экономит ~2,5 минуты), `--adb` / `--emulator` (явные пути).

Перед съёмкой скрипт очищает данные приложения (`pm clear`), поэтому комплект
воспроизводим: те же экраны, те же состояния, тот же порядок.

## Как скрипт управляет приложением

- Дерево интерфейса читается через `uiautomator dump`; элементы ищутся по
  тексту и `content-desc`, координаты берутся из самого дерева. Жёстко
  зашитых координат нет, кроме свайпов по центру экрана.
- Ожидание состояния — по появлению текста («ПОДКЛЮЧЕНО», «ОТКЛЮЧЕНО»,
  «HTTPS-узлов доступно»), а не по таймеру «на глаз».
- Прокрутка — итеративная: скрипт сравнивает текущую высоту элемента с целевой
  и свайпает на разницу, поэтому не зависит от размера экрана.
- Переключение сервисов (Telegram / YouTube / Discord) проверяется по галочке
  внутри строки, а не по цвету.
- VPN-согласие Android (`Connection request`) подтверждается один раз, как это
  сделал бы пользователь.

## Единый вид кадров

Всё делается штатными средствами Android, состояние приложения не подменяется:

- `wm density 400` — чтобы контент экранов помещался в кадр целиком;
- demo mode SystemUI: время 10:08, Wi-Fi с полным уровнем, заряд 92 %,
  уведомления скрыты;
- анимации выключены, heads-up уведомления выключены, экран не гаснет;
- время выставляется через `su 0 date` (на root-образе `google_apis`), на
  нерутованных образах шаг тихо пропускается.

## Что автоматизировано частично

| Шаг | Ограничение |
|---|---|
| Автоподбор DPI-стратегий | Реальная проверка 61 стратегии идёт ~2,5 минуты и требует сети; скрипт ждёт результат до 7 минут |
| VPN-согласие | Системный диалог на английском (язык системы AVD); подтверждается до снимка, в кадр не попадает |
| Время в статус-баре | Нужен root-образ (`google_apis`, не Play Store) |

## Результат

```text
docs/assets/screenshots/
├── raw/                 оригинальные PNG 1080×2400 без оформления
├── extras/              дополнительные экраны
├── manifest.json        описание каждого кадра (экран, состояние, API, ABI, версия)
├── capture-report.md    отчёт: что снято, что нет и почему
├── contact-sheet.png    контактный лист для быстрого просмотра
└── automation/
    ├── capture.py
    └── README.md
```

После обновления приложения достаточно пересобрать APK и запустить скрипт
заново: структура каталогов и имена файлов не меняются, отчёт и манифест
перезаписываются.
